# 《星陨战线》Steam 上线方案：从 demo 到可售卖商品

> 评审对象：`D:\99-agent`（Three.js r158 + DOM UI，1 张图 / 8 波 / 3 位守卫 / 27 枚铭文）
> 结论先说：**Steam 对你不是技术问题，是内容和发行问题。** 打包 3–7 天就能做完；真正要花 6–9 个月的是"让这 10 分钟变成 4–6 小时"，以及"在发布前攒够 1.5 万愿望单"。

---

## 0. 先看清 Steam 和小游戏的根本差异

| 维度 | 微信小游戏 | Steam |
| --- | --- | --- |
| 商业模式 | 免费 + 广告 | **买断 $9.99–14.99** |
| 玩家预期 | 3 分钟上手，随时退出 | **4–6 小时主线，15+ 小时全成就** |
| 失败成本 | 划走 | **写差评，永久挂在商店页** |
| 获量方式 | 分享裂变、买量 | **愿望单 → 算法推荐 → 首页曝光** |
| 内容判定 | 一个玩法循环就够 | 1 张图 8 波 = **demo，不是商品** |
| 合规 | 软著 + 备案 | 基本无（国际版）；国内蒸汽平台才要版号 |
| 技术门槛 | 高（UI 重写 + 性能） | **低（你已经能在浏览器跑）** |

**关键判断：你的资产在 Steam 上更值钱。** 二次元 / 3D / Roguelike 塔防的付费用户集中在 Steam（Rogue Tower 卖 $14.99、生命周期 160–290 万美元；Tangy TD 首发 30 小时 3 万美元），而微信小游戏的休闲用户对硬核 3D 塔防的接受度反而更低。

**所以：Steam 优先，小游戏作为第二平台复用内容。** 但顺序反过来的话，小游戏那套 UI/性能改造对 Steam 没有复利。

## 1. 现在的内容，离"能卖"差多远

| 维度 | 你现在有 | Steam 及格线 | 差距 |
| --- | --- | --- | --- |

| **守卫** | 3 位 × 4 形态（= 12 个"塔阶段"） | 5–8 个原型 | 3 个偏少，但 4 形态是有价值的深度 |

| **局外成长** | 无 | 解锁内容（新塔/新铭文池/难度） | **必须做** |
| **模式** | 单关卡 | 战役 + 无尽 + 每日挑战 | 需要 |
| **成就** | 无 | 20–30 个 | 需要 |

**残酷结论**：现在这个版本直接上 Steam，退款率和差评率会双高。它**已经是一个极好的 demo**——demo 是拿愿望单的工具，但商品需要内容。

## 3. 技术方案：打包与 Steamworks 集成

### 3.1 外壳选 Electron（不要重写引擎）

你的游戏本质是 WebGL 页面，最省的路径是**原样搬进 Electron**：

```
electron/
├─ main.js          # 创建 BrowserWindow、全屏、无菜单栏、单实例锁
├─ preload.js       # contextBridge 暴露 steam.* API
└─ steam.js         # steamworks.js 封装（成就/统计/云/富状态）
```

- **Electron**：跨平台、WebGL/音频/字体行为和你现在浏览器里完全一致，打包 ~150–200 MB（安装包 70–90 MB）。对 Steam 来说完全可接受（Steam 上大量独立游戏是 Electron）。
- **Tauri**：体积小到 10 MB，但 WebView 版本碎片化（Windows 上是 WebView2），**你现在依赖的 WebGL2 + 后处理 + Web Audio 在 WebView2 上需要逐个验证**，不建议首发用。
- **不要迁 Unity/Godot**：你的 3D 是程序化代码生成的（`art.js` 2,526 行），迁移等于重做美术，收益为零。

### 3.2 Steamworks 集成清单

用 [`steamworks.js`](https://www.npmjs.com/package/steamworks.js)（Node 原生模块，必须放在主进程，通过 IPC 暴露给渲染层）：

| 能力 | 用在哪 | 优先级 |
| --- | --- | --- |
| 成就 Achievements | 20–30 个，见 §7 | P0 |
| 统计 Stats | 累计击杀、最高波数、通关次数 | P0 |
| 云存档 Cloud | 用 Auto-Cloud 指向存档文件 | P0 |
| 富状态 Rich Presence | "正在守卫第 5 波" | P1 |
| 排行榜 Leaderboards | 无尽模式最高波数 | P1 |
| Steam 输入 / 手柄 | Steam Deck | P1 |
| Workshop | 自定义波次/铭文（`data.js` 天生可数据化） | P2 |

### 3.3 存档要从 localStorage 迁出来

现在只有 `localStorage` 存静音。Steam 版必须：

- 存档写到 `app.getPath('userData')/save.json`；
- 在 Steamworks 后台配 **Auto-Cloud**：根路径 `WinAppDataRoaming`（或 `LinuxXdgDataHome`），子路径 `你的游戏名/save.json`；
- 存档带版本号 + 迁移函数，否则更新后老存档崩。

### 3.4 Steam Deck 与手柄

Deck 的 Verified 要求四条：**完整手柄支持、1280×800/720 默认分辨率、文字可读、无启动器摩擦**（[官方标准](https://www.steamdeck.com/en/verified)）。

现实建议：**首发目标定 "Playable" 而不是 "Verified"**。

- 先把 1280×800 的 UI 回归做好（现在按 1600×900 设计，小屏字会糊）；
- 加游戏手柄光标（左摇杆移动虚拟指针 + A 确认 + LB/RB 切换卡牌 + X 释放技能），约 1–2 周；
- 手柄映射和图标（Xbox / DualSense）要做，否则不算"完整手柄支持"；
- Electron 在 Proton 下一般能跑，但**建议额外出一个 Linux 构建**（`.AppImage`），Deck 上原生更稳。

### 3.5 桌面端必须补的"商品感"

| 项 | 说明 |
| --- | --- |
| 设置菜单 | 分辨率/窗口/全屏、画质三档、帧率上限、垂直同步、音量分轨、语言 |
| 字体打包 | 现在优先用"楷体/微软雅黑"，**Linux/Steam Deck 上没有**，会 fallback 成黑体。必须子集化打包一份（约 150–250 KB） |
| 无浏览器痕迹 | 禁用右键菜单、禁用 F5/DevTools 快捷键、无地址栏感、启动即全屏 |
| 启动速度 | Electron 冷启动 1–2 秒；配一张启动画面，别让玩家看黑屏 |
| 崩溃处理 | 记录 `crash.log` + 弹窗提示存档位置 |
| 多显示器/缩放 | Windows 125%/150% 缩放下不能错位 |

## 4. 内容扩展：从 10 分钟到 4–6 小时

按"投入产出比"排序，这是**最省钱**的扩法：

### 4.1 先做系统，再做内容（复用率最高）

| # | 做什么 | 为什么最划算 | 成本 |
| --- | --- | --- | --- |
| 1 | **难度三档 + 无尽模式** | 同一张图变 4 份内容，纯数值 + 状态机 | 3–5 天 |
| 2 | **局外星图（内容解锁）** | 给"再来一把"的理由，是 Steam 版的留存骨架 | 1–2 周 |
| 3 | **成就 20–30 个** | 直接拉长时长，玩家会为成就重打 | 3–5 天 |
| 4 | **每日挑战（固定种子）** | 长尾内容，零美术成本 | 3 天 |
| 5 | **图鉴/角色小传** | 二次元玩家最吃这个，纯文本 + 立绘 | 3–5 天 |
| 6 | **IV 阶终阶二选一** | 用现有美术做构筑深度，比新角色便宜 10 倍 | 1 周 |

### 4.2 再做内容（美术成本在这里）

| 内容 | 建议 | 备注 |
| --- | --- | --- |
| 地图 | **3 张**（云海圣所 / 熔火回廊 / 星海遗迹） | `world.js` 已经是参数化的，换配色/路径/装饰即可，每张 3–5 天 |
| 守卫 | 3 → **5 位** | 每位 4 形态 = 4 张立绘 + 3D 变体，一位约 1.5–2 周 |
| 敌人 | 5 → **11 种** | 加：分裂、护盾、治疗者、召唤者、免疫减速、高速冲锋；复用 `EnemyFactory` |
| Boss | 1 → **3 个** | 每图一个，加阶段与技能 |
| 铭文 | 27 → **45** | 提高"机制型"比例到 50% |

### 4.3 明确不要做的

- 不要做剧情动画/配音（成本爆炸，塔防玩家不看）；
- 不要做联机（服务器 + 反作弊 + 匹配，一个小团队会死在这）；
- 不要做关卡编辑器（除非要做 Workshop，那是 P2）。

### 5.3 商店页文案要点

- 第一段（折叠前可见）必须回答：**"这是什么、为什么特别"**——答案就是「融合共鸣：两名同伴合成升阶，改写她的星轨」。
- 用 GIF 展示融合过程（Steam 支持 WebM/GIF）。
- 中英双语：英文不是翻译腔，要重写。

## 6. 发行节奏：愿望单是唯一的硬通货

Steam 算法只看一件事：**发布时的愿望单转化速度**。所以节奏比内容还重要。

| 时间 | 动作 | 目标 |
| --- | --- | --- |
| **T-6 月** | 商店页上线（Coming Soon），发首支预告 | 开始攒愿望单 |
| T-5 月 | 参加 **Steam Tower Defense Fest**（如有） | 一次集中曝光 |
| **T-4 月** | **Demo 上线**（就用现在的 8 波） | Demo 玩家 → 愿望单转化 15–25% |
| **T-3 月** | **Steam Next Fest**（需 Demo 已公开、页面已发布、正式版不能在此期间发） | 单次活动可加 3k–1w 愿望单 |
| T-2 月 | 联系主播/媒体（TD 品类有稳定受众） | 预热 |
| T-1 月 | 定档、发布最终预告、社区活动 | |
| **T0** | 发售，首发 -10~15% | 首周销量 ≈ 愿望单的 10%–30% |

**官方硬规则**：Coming Soon 页面必须在发售前**至少 2 周**公开（[Steamworks 文档](https://partner.steamgames.com/doc/store/types)）。实际建议 **3–6 个月**，因为愿望单是复利。

**基准数据**（给你定目标的锚）：
- 愿望单 → 首周销量中位数 **10.5%**（GameDiscoverCo 三个月样本）；
- 表现好的塔防：1 万愿望单 → 30 小时 3 万美元（Tangy TD，$9.99）；
- Rogue Tower：$14.99，生命周期 160–290 万美元。

**目标：发售前 1.5–2 万愿望单。** 低于 5 千建议延后。

## 7. 定价与商业模型

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 价格 | **$9.99–14.99**（国区 ¥38–58） | 塔防+Roguelike 的常规带；3 张图卖 $9.99 更稳 |
| 首发折扣 | 10–15% | 拉首周转化 |
| 区域定价 | 用 Steam 推荐值，国区单独下调 | 中文玩家是你的基本盘 |
| DLC | 原声带 $3.99、支持者包 | 低成本增收 |
| **不要** | 免费 + 内购、广告、体力 | Steam 玩家对这套极度反感 |

**收入估算（保守）**：1.5 万愿望单 × 12% ≈ 1,800 份首周；$9.99 × 0.7（分成+税）≈ $7/份 → 首周约 **$1.2 万**；加上长尾和促销，首年 3–5 万美元是合理区间。**这不是一个能靠收入决定要不要做的项目，而是一个能建立 IP 和口碑的项目。**

## 8. 本地化

| 语言 | 优先级 | 说明 |
| --- | --- | --- |
| **英文** | 必须 | Steam 最大市场，没有英文等于放弃 60% 曝光 |
| 简体中文 | 已有 | 但要从硬编码抽出来 |
| 日文 | 建议 | 二次元标签加权，成本 $300–800 |
| 韩文 | 可选 | 二次元接受度高 |

**工程改造**：现在所有文案硬编码在 `index.html` / `data.js` / `game.js` 里。需要：

1. 抽 `i18n/zh-CN.json` + `en.json`（预估 400–700 条）；
2. `data.js` 的 `name/desc/quote` 改成 key；
3. 字体子集化（打包一份含中英日的字体，或按语言分包）；
4. 英文排版回归（英文比中文长 30–50%，UI 会溢出）。
