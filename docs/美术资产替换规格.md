# 星陨战线 · 美术与 3D 模型替换规格

> 这份文件单独维护，用来约定后续替换塔、小兵、卡面和 3D 模型时需要的文件格式、尺寸、命名与验收标准。
>
> 当前版本：
> - 塔的卡面是 512×640 PNG。
> - 妖怪小兵是 128px 高的横向精灵图（9 或 12 帧）。
> - 塔和普通小兵的 3D 模型目前是 `js/art.js` 内的程序化几何，不是外部 GLB。
> - 后续替换 3D 模型时，按本文件提供 GLB，我再接 `GLTFLoader` 和动作状态机。

---

## 1. 替换优先级

建议按这个顺序替换：

1. **五位塔的 I–IV 阶 3D 模型**：玩家看得最多，也最影响“升级有没有变化”。
2. **五位妖怪小兵**：已经有 2D 精灵，可继续补 3D 版或高清 2D 版。
3. **Boss 深渊歌姬**：单独做一套三阶段模型/立绘。
4. **塔卡面 I–IV**：如果 3D 模型和卡面不一致，优先统一。
5. **普通小兵 shade / runner / brute / wisp**：可先沿用现有 3D，只换贴图或整体 GLB。

## 2. 当前资产映射

### 2.1 塔卡面

| 槽位 | 当前路径 | 尺寸 | 格式 |
| --- | --- | --- | --- |
| 星弦 I–IV | `assets/cards/archer-1.png` … `archer-4.png` | 512×640 | PNG RGBA |
| 霜语 I–IV | `assets/cards/mage-1.png` … `mage-4.png` | 512×640 | PNG RGBA |
| 月刃 I–IV | `assets/cards/blade-1.png` … `blade-4.png` | 512×640 | PNG RGBA |
| 焰麟 I–IV | `assets/cards/kirin-1.png` … `kirin-4.png` | 512×640 | PNG RGBA |
| 灵参 I–IV | `assets/cards/ginseng-1.png` … `ginseng-4.png` | 512×640 | PNG RGBA |

替换要求：

- 四阶必须是**同一个角色的连续成长**，不能换人。
- 角色脸部/发型/主色保持一致；阶位变化放在服装、武器、灵兽、光环、构图。
- 建议保留头顶到脚底的完整构图；重要信息不要贴边 48px。
- 不要在图内画 UI 边框、阶段罗马数字或文字，这些由游戏叠加。
- PNG、sRGB、透明或深色背景均可；若背景透明，人物边缘不要有白边。
- 推荐 1024×1280 作为 2× 版本，文件仍按 512×640 命名由引擎缩放也可。

### 2.2 塔 3D 模型

当前由 `js/art.js` 的 `CharacterFactory.create(type, level)` 生成，阶位已经影响：

- 阶段 II：狐面/红绳/肩甲/背帛
- 阶段 III：灵能狐尾、冰晶翼、焰羽翼、光环
- 阶段 IV：冠冕、神环、神降披帛、更大翼展

游戏内还会叠加：

- 阶位地面环（I 青铜 / II 冰蓝 / III 紫 / IV 金）
- 星辉强化环（0–3 圈）
- 阶位整体缩放

如果替换为外部模型，建议每个塔每个阶位一个文件：

```text
assets/models/towers/archer-1.glb
assets/models/towers/archer-2.glb
assets/models/towers/archer-3.glb
assets/models/towers/archer-4.glb
assets/models/towers/mage-1.glb
...
assets/models/towers/blade-4.glb
assets/models/towers/kirin-1.glb ... kirin-4.glb
assets/models/towers/ginseng-1.glb ... ginseng-4.glb
```

**GLB 规范**

| 项目 | 要求 |
| --- | --- |
| 坐标系 | Y-up，角色正面朝 **+Z**，脚底中心在原点 `(0,0,0)` |
| 单位 | 1 单位 = 1 米；塔高约 **2.1–2.4**，Boss 高约 **5.5–7** |
| 朝向 | 不要烘焙旋转；根节点不要有 90° 修正 |
| 缩放 | 应用全部缩放，导出时 scale=1 |
| 材质 | PBR 或 Toon；最多 4 个材质；贴图内嵌或放在同目录 |
| 贴图 | 单张 ≤2048；角色主贴图建议 1024；sRGB |
| 面数 | 塔 8k–20k tris；小兵 3k–8k；Boss 20k–40k |
| 灯光/相机 | 不导出灯光、相机、地面、参考板 |
| 动画 | `Idle`、`Attack`、`Cast`、`Hit`、`Death`（塔可只有 Idle/Attack/Cast） |
| 帧率 | 30fps；动作从第 0 帧开始；Idle 循环 |
| 根运动 | 不要 root motion；位移由游戏控制 |
| 命名 | 根节点 `Root`；骨骼可用 Mixamo 命名，但不要带命名空间 |

**四阶轮廓要求**

| 阶段 | 必须能一眼看出的变化 |
| --- | --- |
| I 灵契 | 素装、武器基础形态、灵兽幼体 |
| II 少女 | 增加肩甲/披帛/腰饰，武器出现发光纹 |
| III 觉醒 | 背后出现翼/尾/冰晶/焰羽，出现光环 |
| IV 神降 | 冠冕、双翼展开、武器终形、明显更大的轮廓 |

不要只靠“换颜色”区分阶位；至少 25% 的剪影变化，游戏镜头是俯视远景。

### 2.2b 灵兽守卫（焰麟 / 灵参）

当前 3D 为程序化灵兽：

- **焰麟**：四足、冠角、火焰鬃尾；II 阶增加副角，III 阶展开焰翼，IV 阶出现神环。
- **灵参**：根体、叶冠、根须手臂与浆果；II 阶出现根环，III 阶展开森罗光晕，IV 阶神降光冠。

如果替换为 GLB，建议沿用 `kirin-1..4.glb` / `ginseng-1..4.glb` 命名，并按灵兽体长而非人形身高控制尺寸：焰麟约 2.6–3.2 体长，灵参约 2.0–2.4 高；脚底/根底仍在原点。

### 2.3 小兵 2D 精灵（当前已接入）

| 类型 | 路径 | 尺寸 | 帧数 |
| --- | --- | --- | --- |
| 火麒麟 | `assets/yokai/kirin.png` | 1152×128 | 9 |
| 付丧神 | `assets/yokai/tsukumo.png` | 1536×128 | 12 |
| 飞头蛮 | `assets/yokai/rokurokubi.png` | 1536×128 | 12 |
| 菌妖 | `assets/yokai/mushroom.png` | 1152×128 | 9 |
| 人参精 | `assets/yokai/ginseng.png` | 1536×128 | 12 |

替换要求：

- **横向条带**：从左到右逐帧排列，不要网格图集。
- 每帧为正方形；当前 128×128/帧。
- 总宽 = 帧数 × 128；帧数 9 或 12（更多也可，加载器按 `宽/高` 自动计算）。
- PNG RGBA、sRGB、透明背景。
- 脚底/底部对齐同一基线，帧内不要上下跳动；跳动由引擎做。
- 不要画投影、地面、UI、文字。
- 当前引擎**不按路径方向翻转**；请统一朝左（与现有图一致），或者提供左右两套并在文件名标注 `-left/-right`。
- 建议 2× 版本：256px 高，总宽 2304/3072，仍然可以直接替换。

### 2.4 小兵 3D 模型（未来替换）

当前普通小兵由 `js/art.js` 的 `EnemyFactory.create` 生成：

| 类型 | 当前定位 | 高度/半径 | 飞行 |
| --- | --- | --- | --- |
| shade 蚀影 | 基础群怪 | 2.0 / 0.55 | 否 |
| runner 影狼 | 高速 | 1.5 / 0.50 | 否 |
| brute 铁卫 | 重甲 | 3.1 / 0.82 | 否 |
| wisp 飞灵 | 空中 | 1.2 / 0.45 | 是，飞行高度 1.55 |
| boss 深渊歌姬 | Boss | 6.0+ / 1.40 | 否 |

未来路径：

```text
assets/models/enemies/shade.glb
assets/models/enemies/runner.glb
assets/models/enemies/brute.glb
assets/models/enemies/wisp.glb
assets/models/enemies/boss.glb
```

要求：

- 同样 Y-up、正面 +Z、脚底原点。
- `shade/runner/brute/wisp` 至少 `Idle`、`Walk`、`Attack`、`Death`。
- `wisp` 可以悬浮，但原点仍放脚底/悬浮基准。
- Boss 需要 `Idle`、`Cast`、`Summon`、`Death`，并预留三阶段挂点。
- 面数：普通 3k–8k，Boss 20k–40k。
- 不要烘焙路径、阴影和碰撞体。

## 4. 交付方式与验收

### 交付前检查

- [ ] 文件名、目录、大小写完全一致。
- [ ] 没有中文文件名、空格、括号。
- [ ] 所有贴图都在 GLB 内，或与 GLB 同目录并写相对路径。
- [ ] 角色脚底在 `(0,0,0)`，正面朝 `+Z`。
- [ ] 四阶塔放在同一套骨骼/同一套动作上，便于切换。
- [ ] 2D 小兵每一帧基线一致，透明背景无白边。
- [ ] 卡面四阶是同一角色。
- [ ] 提供来源/版权说明；如果是外部素材，写进 `THIRD_PARTY_NOTICES.md`。

### 我这边接入后会验证

1. `file://` 直接打开仍可加载，不需要本地服务器。
2. 塔 I–IV 模型、颜色、地面环、强化环一致。
3. 小兵动画循环、受击、死亡与血条位置正确。
4. 手机端不处理；桌面 1366×768 与 1600×900 不溢出。
5. 性能：普通波次 100+ 敌人时仍保持可玩帧率。

## 5. 现在最需要你提供的

如果只做一批，建议先给：

1. **星弦/霜语/月刃 的 I–IV 阶 GLB 各一套**（共 12 个文件）。
2. **Boss 深渊歌姬** 的三阶段 GLB 或三张全身立绘。
3. 其余小兵先用现有 2D/程序化模型，等塔和 Boss 稳定后再替换。

如果暂时没有 GLB，也可以先给：

- 四阶塔的**正视、侧视、背视三视图**（每阶 3 张）+ 主色/武器说明；
- 我按三视图继续做程序化 3D，这样不依赖外部模型加载器也能保持 `file://` 可玩。
